More complete request statistics, a prebuilt Docker image, a memory leak fix
in lite, and simpler lyrics routing. **macOS packages are discontinued**: on
a Mac, run the Docker image.

## Docker

- **Prebuilt image** `ghcr.io/itouakirai/wrapper` (`latest`, `3.0.4`,
  `3.0`, and `nightly` for the newest commit). No more building from source:
  download `compose.yaml` and `.env.example`, set a token,
  `docker compose up -d`. The README has a full Docker guide: settings,
  updating, backups, public mode, reverse proxy, macOS, troubleshooting.
- `compose.yaml` takes every setting from `.env`: token, public mode,
  maximum accounts, proxy, log level, data directory, bind address and port.
  It restarts the container automatically.
- **Accounts start on hosts that restrict user namespaces** (Ubuntu 24.04
  and others). The container now gets `cap_add: SYS_ADMIN`, and the agent,
  running as root with that capability, uses its privileged sandbox (mount +
  PID namespace, no user namespace). Previously lite failed there with
  `/proc/self/uid_map: Operation not permitted`. `WRAPPER_RUNTIME` (or
  `--runtime`) overrides the choice; the startup log names the sandbox in
  use.
- Empty `WRAPPER_*` variables now mean "not set" (`WRAPPER_MAX_ACCOUNTS=`
  used to be rejected).
- Building from source (`docker build .`) works again: the NDK step failed
  for the default NDK r23b (thanks @daylighttg, #2). The builder uses the
  current Rust and Node, and builds with CMake 4.

## macOS

There are no macOS packages from this release on: GitHub's macOS runners
were too scarce to build them reliably. Run the Docker image with Docker
Desktop (Apple Silicon: with Rosetta), see the README's Docker section.
Migrate your accounts with **Backup → Directly from another server**, or a
backup file. `wrapper update` on an existing macOS install reports that
there is no build for the platform.

## Statistics

- **Every attempt counts against its account.** A request that failed on
  one account and was retried on another used to count only for the account
  that answered last. Now each account's counters include every request it
  handled, failures and connection errors included, so the success rate per
  account is accurate. Overall totals still count each client request once.
- Each account keeps a **30-day daily history** and the time of its **last
  success**. Existing `stats.json` files are migrated: today's counts carry
  over.
- Requests that **no account could take** (none running for that
  storefront) are counted separately and shown under *All time*.

## Public page and dashboard

- **Range switch**: Today / 7 days / 30 days / All time for the endpoint
  tiles, with the success rate and failure count of each endpoint.
- The daily chart shows **successes and failures stacked**.
- **Account table**: requests, failures and success rate for the chosen
  range, a 14-day trend, all-time total and last use. Sort by any of these;
  a totals row sums every account.
- **Click an account** for its details: every endpoint for today, 7 days,
  30 days and all time, successes, failures and success rate, when it was
  added and last succeeded, and its own 30-day chart.
- *Your accounts* show today's requests and the success rate, with a
  **Details** button that opens the account in the table.

## Fixes

- **lite: memory leak in `/key`.** The persistent key and decrypt contexts
  were never released, leaking a few KB per key request. Long-running
  instances no longer grow.
- **Behind nginx**, live updates in the panel (`/api/events`) were held back
  by proxy buffering. The agent now sends `X-Accel-Buffering: no`.
- **/lyrics routing** uses the catalog's `hasLyrics` from the same lookup as
  the other endpoints instead of a separate per-region lyrics probe. Storefronts
  that report lyrics are preferred; if none does, every storefront that has the
  song is tried. `language` and `script` are passed to lite unchanged and
  requests are retried on another account like the other endpoints.

## Upgrading

- Packages: `wrapper update` (stop the panel first), updating the binary and
  the QEMU guest / rootfs together (the default). Android: install the new
  APK.
- Docker: switch to the prebuilt image. Take the new `compose.yaml` (it
  adds `cap_add: SYS_ADMIN`) and `.env.example` (your data stays in
  `./rootfs/data`), then `docker compose pull && docker compose up -d`.
- Running `wrapper agent` as root on Linux now uses the privileged sandbox
  by default (`--runtime sandbox` keeps the rootless one).
